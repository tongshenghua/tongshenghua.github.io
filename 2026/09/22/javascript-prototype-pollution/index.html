对象里到底藏着什么

先从最普通的一个对象说起。

我写了两个属性，name 和 age。但有意思的是，下面这些也是能访问的：

我并没有写这两个东西。那它们是哪来的？

答案是：user 除了自己的属性，还挂着一个”备用的对象”。当你在 user 身上找不到某个属性时，JavaScript 会去那个备用对象里再找一遍。这个备用对象，就是原型（prototype）。

Object.getPrototypeOf() 是个静态方法——传一个对象进去，返回它的原型

所以 user 的原型就是 Object.prototype。toString 和 hasOwnProperty 都存在它上面，user 于是”继承”到了它们。

这里有个容易被忽略的点：原型不是一个对象私有的，是大家共用的。

两个完全不相干的对象，指向同一个原型对象。这就像两个人都把同一个抽屉当备用箱——你在抽屉里放个东西，另一个人打开抽屉也能看到。

区别只在于 __proto__ 写起来短，而且能直接放在赋值号左边。它出镜率高，一半是图方便，一半是历史原因——早期浏览器就是这么实现的，后来才被正引进标准。

__proto__ 严格来说并不是 JavaScript 的关键字。它只是定义在 Object.prototype 上的一个属性，而且是个访问器属性（带 getter 和 setter）。先记住这一点，等下讲 JSON.parse 的时候会用到它。

为什么一定是 true？

因为用 {} 这种字面量写出来的对象，JavaScript 在建它的时候就把原型设成了 Object.prototype。这不是巧合，是规定——{} 其实等价于 new Object()，而 Object 这个构造函数的 prototype 属性，指向的正好就是 Object.prototype。

换句话说，你随手敲的每一个 {}，都在往同一个点上连。

这就是原型污染：攻击者往原型链的共享节点上写数据。

那攻击者怎么才能写进去

到这儿你可能觉得，这不算漏洞啊——a.__proto__.name = 'x' 是我自己在控制台敲的，我想敲就敲，不想敲就不敲。

对。能访问 __proto__ 不是漏洞。漏洞出在”程序把用户输入写到了那个位置”。

问题在于，JavaScript 里有一类很常见的操作：把一串数据里的 key，当成属性名挨个写进另一个对象。这种写法本身没毛病，甚至可以说是必需品。但如果那串数据来自用户，性质就变了。

看个例子。TryHackMe 那个房间里的社交网站有个「克隆相册」功能——用户选中一个相册，填个新名字，后端就复制一份出来。这个功能最核心的一行是：

为什么这个漏洞特别难防

看完上面三个例子，应该能感觉到一件事：被改坏的东西，往往不是写错的那部分代码。

merge 没错。qs 也没错。Object.prototype.toString 本身更没有错——它是 JavaScript 语言的一部分。

攻击者污染的是一个所有人都在用的共享基础设施。他不需要知道 qs 的存在，只需要挑一个足够底层、足够通用的属性名去覆盖，剩下的交给调用链自己去撞。

这也解释了为什么静态扫描工具很难发现它。SQL 注入有拼接的固定特征，eval 有明确的关键字。而原型污染问的是：

用户能控制的字符串，最后有没有走到”属性名”的位置？

这是数据流问题，不是语法特征问题。而且攻击者控制的不是值，是 key。同样一个 merge 函数，用在配置合并上完全安全，用在用户输入上就致命——工具没法从函数本身判断语境。

几个踩过的坑

记下来，因为这些细节才是自己动手时真正卡住人的地方。

专辑名必须一字不差。 触发 merge 的前提是能通过相册名找到目标对象。名字对不上，函数直接跳过，请求返回 200 但什么都没发生——看起来像”payload 没生效”，其实是压根没走进漏洞代码。

污染不会自己消失，只能重启。 Object.prototype 上的改动存在进程内存里。打完 DoS 之后进程已经死了，不重启服务，下一个 payload 根本发不进去。做多轮测试时每一轮之间都要重启。

“原型污染”这个标签有时候用得比较松。 房间里第一个 XSS 利用用的是 _.set 的任意路径写入，压根没碰 __proto__。看资料的时候要自己分清：改一个对象，和改整个进程的原型，是两种不同的东西。

房间文案本身有笔误。 服务端代码片段里写的是 _.set(friend, input.path, payload.value)，但 payload 根本没定义，应该是 input.value。以实际回显为准，不要以题目文案为准——这在所有靶场里都成立。

最后

回到开头那个 merge 函数。它没有 bug。

它只是安静地执行了一件事：把 from 的每一个 key 写进 to。

而攻击者做的事情也很简单——他不改变任何一个值，他只改变一个属性的名字。

这就是原型污染的全部内核。当你控制的不再是属性的值，而是属性的名字时，你控制的就不再是数据，而是程序的形状。
